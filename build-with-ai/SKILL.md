# Build with AI

用 AI 协作构建产品的标准流程。

## 什么是 Build with AI

这是一个人机协作构建产品的流程框架：
- **人类** 出想法、做决策
- **AI** 执行建议、协助文档、代码开发

## 什么时候使用

- 用户想要构建一个新产品
- 用户想要用 AI 协作方式开发产品
- 用户不确定产品开发流程该怎么做

## 流程概览

```
第一步：想法 & 草图 → 第二步：产品文档 → 第三步：开发
```

| 步骤 | 执行者 | 输出 |
|------|--------|------|
| 第一步 | 人类（Gump） | 草图、产品想法、功能、人群 |
| 第二步 | 人类 + AI 协作 | 核心流程、功能列表、页面结构、数据设计 |
| 第三步 | AI Coding | 代码、测试、部署 |

## 详细流程

### 第一步：想法 & 草图

**执行者**：人类

**要做的事情**：
1. 提出想法 - 描述问题和初步想法
2. 画草图 - 用 Excalidraw 或示意图
3. 明确要素 - 产品定位、主要功能、面向人群

**输出**：
- 草图文件（.md 格式，Excalidraw）
- 产品定位
- 主要功能
- 面向人群

**触发关键词**：
"新建产品"、"新想法"、"画草图"、"产品想法"

### 第二步：产品文档

**执行者**：人类 + AI 协作

**要做的事情**：
1. 完善核心流程 - 4 步流程（收集 → AI 解读 → 管理 → 发布）
2. 详细功能描述 - 每个功能的详细说明
3. 页面结构 - 管理系统菜单、页面
4. 数据设计 - 数据库表结构思路
5. 技术选型 - 前端、后端、存储等

**输出**：
- 核心流程文档
- 功能列表
- 页面结构
- 数据设计
- 技术选型

**触发关键词**：
"完善产品文档"、"写需求"、"产品设计"、"详细功能"

### 第三步：开发

**执行者**：AI Coding（人类监督）

**要做的事情**：
1. 技术选型确认
2. 项目初始化
3. 代码实现
4. 测试
5. 部署

**输出**：
- 可运行的产品代码

**触发关键词**：
"开始开发"、"写代码"、"coding"、"开发"

## 核心原则

1. **先想清楚再做** - 不着急写代码，先把需求盘明白
2. **文档驱动开发** - 没有文档不开发
3. **AI 协作** - 人类出想法，AI 执行和建议
4. **迭代优化** - 随时根据反馈调整

## 使用方法

1. 询问用户当前处于哪个阶段
2. 根据用户需求，引导进入对应的步骤
3. 每个步骤按照对应的参考文档执行
4. 确认完成后，再进入下一步
